# 의성 데모: 확산 예측부터 AI 제안 생성까지

2025-03-22 의성 산불(안평면 괴산리)을 상황도 화선 보고 4번(12:50 · 13:10 · 13:45 · 14:20)마다
**입력 → 1 확산 예측(ELMFIRE) → 2 규칙 판정 → 3 LLM 대응 생성(EXAONE + RAG) → 출력** 순서로 실제로 돌려
회차별 제안서를 만든다. 결과는 한 장짜리 뷰어 HTML로 본다. **코드 · 데이터 구조와 디버깅 방법은
[`docs/의성-데모-구조서.md`](../../docs/의성-데모-구조서.md)**, 입력 데이터는 `demo-uiseong/input/README.md`.

```

  → step1_spread.py  8시간 예측(덱 고정 보정, 11/9) → P0 ~ P8 · 뒤 상황도 검증            → round_k/01_spread/
  → step2_rules.py   rules.Inputs → build_llm_input(판정 16묶음 + 12개 항목)              → round_k/02_rules/

                     → 검사(판정 값 · 근거 · 권한 · 형식) → 1회 다시 → 근거 표기 · 조립     → round_k/03_rag · 04_llm · 05_output/
  → round_k.json → build_viewer.py → viewer.html · verify.py → 검증_보고.md
```

**11/8 재설계(사용자 결정):** 규칙 엔진은 규칙으로 판단할 수 있는 것만 판정해 넘기고, 무엇을 할지는 LLM이
표준매뉴얼 · 법령 검색 결과에서 골라 쓴다. 11/7 형식의 문단 자리(topic · anchors)와 11/8 오전의 고정문(`agent/fixed.py`)은 없앴다.

## LLM 대응 생성(agent/, 11/8 재설계)

- **넘기는 것:** 규칙 엔진 항목의 판정만 — `finding` · `facts` · `withheld` · `do_not_state` · 조립기 목록 · 표 · ※(`agent/judgment.py`).
  문단 자리(action의 topic · anchors · see) · `anchor_basis` · 조립기 고정 문장은 넘기지 않는다
- **상황 깃발 · 항목별 작성 지침(11/8 밤):** 회차마다 bundles에서 상황 깃발(지금 대형산불 · 8시간 안에 대형산불 · 작은 불 · 단계 오름 ·
  지휘권 바뀜 · 도지사 · 밤 · 일몰 · 바람 세짐 · 위험 도로 …)을 만들고(`agent/situation.py`), S1 ~ E6마다 깃발로 켜지는 지침 줄을
  프롬프트에 넣는다(`agent/guides.py`): 쓸 것 · 덧붙일 제안(켜질 때만 그 주제를 고를 수 있음, 예: 대형산불 → S6 「통합지휘본부 운영」) ·
  쓰지 않을 것 · 더할 검색 질의. 지침에는 판정 값을 적지 않고, 지침의 조치도 근거 발췌에 있을 때만 쓴다
- **판정 값 상황 문장(11/8 밤):** S1 · S2 · S3의 값이 들어가는 주제는 상황 문장을 `agent/situate.py`가 판정 facts로 쓰고(단계 · 기준별 값 ·
  기준을 넘는 시각 · 지휘권자 · 주택 동수 · 송전선 구간 · 투입 수 · 동원 범위), LLM은 그 뒤의 할 일 문장만 쓴다. 문단 = 상황 문장 + 할 일 문장
- **근거 검색:** 항목마다 질의(항목 범위 · 이름 + 판정 요약 · 범위 + 상황 · 다룰 주제마다 하나) → 상위 10개 + 켜진 지침 질의마다 2개 +
  규칙 엔진 판정 근거(`rule_basis`, 쪽은 조각으로 펼침)(`agent/retrieve.py`)
- **프롬프트:** 지시문(근거에 적힌 조치만, 판정 값 그대로, 지금 할 일과 앞으로의 일 구분, 읽는 사람에게 「~하십시오」, 대상 모아 쓰기) +
  다른 항목 목록 + 읽는 사람의 권한(도지사면 「의성군수에게 …하도록 지시하십시오」) + 상황(+ 「이번 상황」 한 줄) + 판정 + 다룰 주제 +
  작성 지침 + 값을 가린 v3 문단 꼴 예시 + 판정 자료 + 근거 발췌(`agent/prompt.py`)
- **출력:** json_schema로 묶은 `{"proposals": [{topic, category, text, evidence, quote}]}`. topic은 다룰 주제 + 켜진 덧붙일 주제 중에서,
  evidence는 그 호출에 준 청크 ID만 고를 수 있다. 근거 표기는 `agent/cite.py`가 evidence로 만든다(LLM은 괄호를 쓰지 않음)
- **검사:** 근거 없음 · 다룰 주제 빠짐 · 판정에 없는 숫자/시각/수사/단계/이름 · 지도에도 없는 「○○리」 · 입력 설명 옮김 · 할 일 부정 ·
  「~하십시오」 없음 · 방법 빠진 말 · 4문장 · 450자 · 권한 · 「최소 N동」 · 「등」 · 항목 금칙 · 반복 · 대상만 바꿔 나눈 제안(`agent/check.py`).
  시도 3번, 끝까지 걸린 제안만 뺀다
- **화면:** 제안 문장만 보이고, 근거 표기 · 근거 문장 · 원문 발췌는 문단에 마우스를 올리면(누르면 고정) 보인다(`viewer_template.html`)
- 추론 모드는 기본 끔(`--thinking`), 입력(판정 · 상황 · 켜진 지침)이 직전 회차와 같은 항목은 직전 제안을 다시 쓴다
